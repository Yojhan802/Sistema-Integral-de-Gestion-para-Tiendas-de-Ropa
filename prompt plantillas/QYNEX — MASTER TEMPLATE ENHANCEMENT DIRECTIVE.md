# 05. DO NOT MODIFY THE DATABASE WITHOUT NECESSITY

Visual improvements must not automatically produce database changes.

Animations, layouts, visual components, transitions and microinteractions normally belong to:

```text
HTML
CSS
JavaScript
existing frontend architecture
```

If existing data already supports the experience:

DO NOT modify the database.

DO NOT create unnecessary columns.

DO NOT create unnecessary tables.

DO NOT modify backend contracts merely to simplify visual implementation.

Only propose a database/backend change if a genuinely required feature cannot be implemented safely using existing data.

Before doing so:

1. Identify the limitation.
2. Explain why the existing model cannot support it.
3. Prefer the smallest compatible change.
4. Preserve backwards compatibility where possible.
5. Never invent business data solely for visual decoration.
